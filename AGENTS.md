# Repository Guidelines

## Project Structure & Module Organization
- `src/`: Application code (components, lib, data, types). Use `@/...` alias for imports.
- `public/`: Static assets served as-is. Reference with `/asset.png` or import when appropriate.
- `dist/`: Production build output (generated by Vite).
- `context/xsai/`: External workspace with libraries and tests (pnpm + Vitest).
- Root config: `vite.config.ts`, `tailwind.config.js`, `eslint.config.js`, `tsconfig*.json`, `.env.example`.

## Build, Test, and Development Commands
- `npm run dev`: Start the Vite dev server.
- `npm run build`: Type-check (`tsc -b`) and build for production.
- `npm run preview`: Preview the production build locally.
- `npm run lint`: Run ESLint across the project.
- Tests (xsai workspace): `cd context/xsai && pnpm test`. Single test: `pnpm vitest run <path/to/file.test.ts>`.

## Coding Style & Naming Conventions
- Language: TypeScript with `strict` enabled; no implicit anys; keep types close to usage.
- Formatting: 2-space indentation; keep files small and cohesive.
- Imports: Use `@/` alias for `src` (configured in tsconfig and Vite).
- Styling: Tailwind CSS utility classes; prefer composition over custom CSS.
- Naming: `camelCase` for variables/functions, `PascalCase` for React components, `SCREAMING_SNAKE_CASE` for env keys.
- Linting: Follow ESLint rules; fix warnings before PRs.

## Testing Guidelines
- Framework: Vitest is used in `context/xsai` packages; test files end with `*.test.ts`.
- Scope: Add unit tests for utilities and pure logic; component behavior should be exercised where feasible.
- Run: `cd context/xsai && pnpm test` for full suite; use `--coverage` when changing shared utils.

## Commit & Pull Request Guidelines
- Commits: Use Conventional Commits (e.g., `feat:`, `fix:`, `refactor:`, `perf:`, `chore:`) as in existing history.
- PRs: Provide a clear description, link related issues, and include screenshots/GIFs for UI changes.
- Quality gates: Ensure `npm run lint`, `npm run build`, and relevant tests pass before requesting review.

## Security & Configuration Tips
- Copy `.env.example` to `.env`. Do not commit secrets. For Vite, client-exposed keys must be prefixed with `VITE_`.
- Avoid large binary assets in repo; place shared assets in `public/` and import others via `src/`.
